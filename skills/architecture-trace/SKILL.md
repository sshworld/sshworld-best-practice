# Architecture Trace

정적 다이어그램은 **구조**를 보여준다. 요청이 실제로 어느 경로를 타는지, 어디서 지연이 쌓이는지, 의존성이 죽으면 무슨 일이 나는지 — **행위**는 못 보여준다. 이 스킬은 요청을 한 홉씩 따라가며 현재 상태를 말로 적는 다이어그램을 만든다.

산출물은 HTML 한 파일. 빌드도 의존성도 없다. 위키·RFC·PR 본문에 그대로 넣을 수 있다.

## ⚠️ 이 repo 에서의 위치 — 먼저 읽을 것

이 스킬은 **plan-dev 파이프라인의 일부가 아니다.** 설계 문서(`docs/design/<slug>.md`)의 규약과 충돌하지 않도록 세 가지를 지킨다:

1. **구조 델타를 대체하지 않는다.** 설계 문서 3번 블록(구조 델타)의 원본은 여전히 mermaid 다. 트레이스는 **흐름이 있는 작업에만** 추가로 붙는 별개 산출물이다. 노드 6개짜리 `지금 → 이후` 그림에 애니메이션을 얹으면 정보량만 늘고 더 안 읽힌다.
2. **생성물이다 — 동기화 의무가 없다.** `EDGES` 의 `d` 문자열은 좌표 산술이라 노드를 하나만 옮겨도 전부 깨진다(mermaid 가 대신 해주던 계산이 바로 이것). 그래서 **원본은 mermaid, 트레이스는 필요할 때 재생성**하고, 코드와 어긋나도 고치지 않는다. rot 은 **동기화 의무가 있을 때만** 부채다 — 의무를 명시적으로 없애 소모품으로 규정한다.
3. **repo 에 커밋할지는 그때 판단.** 발표·온보딩·RFC 처럼 볼 사람이 정해진 순간에 만들고, 그 자리에서 소비하는 것을 기본으로 한다. 커밋한다면 `docs/design/` 밖에 두고 "생성 시점" 을 파일 안에 적는다.

> 하네스 짝이 없는 **콘텐츠 전용** 스킬이다. 스킬 호출은 hook 으로 강제할 수 없다(Stop hook 은 turn 재개만 가능, 액션 지정 불가) — `fork` 와 같은 정당한 예외.

## 절대 규칙 — 토폴로지와 트레이스를 분리한다

자료구조 셋, 그리고 그것만 재생하는 플레이어:

```js
const NODES     = { id: {x, y, t:'라벨', k:'서브라벨'} }   // 좌표 + 라벨
const EDGES     = { id: 'M114 180 H160' }                  // SVG path d 문자열
const SCENARIOS = { '이름': [ step, step, ... ] }           // 흐름 하나당 배열 하나
```

단계를 렌더 코드에 하드코딩하지 않는다. 컴포넌트 추가 = `NODES` 한 줄, 흐름 추가 = `SCENARIOS` 배열 하나. 이 분리가 유지보수 가능성의 전부다.

`assets/trace-template.html` 이 아래 내용을 전부 구현한 동작하는 파일이다. **처음부터 쓰지 말고 이걸 열어 고쳐라.**

## step 스키마

```js
{e:'gs'}                       // 엣지 통과, 점이 정방향
{e:'gs', back:1}               // 역주행 — 응답 레그
{e:'ga', err:1}                // 빨간 선, 빨간 점
{n:'cache', s:'ok'}            // 노드 상태: undefined | 'ok' | 'err'
{par:[{e:'sc'},{e:'sq'}]}      // fan-out: 한 단계에 동시 레그
{l:'SELECT … WHERE id=8821'}   // 상태줄 문구
{ms:38}                        // 지연 기여분, 메타줄에 누적
```

`l` 과 `ms` 는 어느 단계에나 붙일 수 있다. 나머지는 선택.

## 시나리오 — 최소 3개, 실패 필수

1. **정상 경로** — 모두가 이미 머릿속에 그리는 흐름
2. **저하 경로** — 캐시 미스, 재시도, 콜드 스타트, 폴백
3. **실패 경로** — 인증 거부, 타임아웃, 차단. 점이 중간에 멈추고 **빨갛게 되돌아와야** 한다

**실패 시나리오가 이 산출물의 값을 번다.** 리뷰어는 실패 모드를 두고 논쟁하고, 성공만 보여주는 다이어그램은 장식이다. 이건 설계 문서의 기준선 3형태·`미검증` 자백과 같은 뿌리다 — 저자가 실패 경로를 **열거하도록 강제**하는 장치.

`par` 는 **진짜 동시**일 때만 쓴다. 순차 호출을 병렬로 그리면 거짓말이 된다. 없는 동시성을 연출로 만들지 말 것.

## 배치

노드를 손으로 격자에 놓는다. 눈대중 자동배치 금지.

- 노드 박스 104×46, 라운드 9. 중심은 가로 160px / 세로 116px 격자
- 요청은 왼쪽 → 오른쪽. 세로 오프셋은 **분기**를 뜻하지 순서가 아니다
- 엣지: 같은 행 이웃은 직선(`M142 190 H198`), 행이 바뀌면 3차 베지어. **선이 노드 박스를 관통하면 안 된다**
- 엣지 끝점은 노드 **가장자리**에서 계산한다 (중심 ±52 가로, ±23 세로). 중심에서 계산하면 점이 박스 밑에서 출발한다
- 노드 수 상한은 두지 않는다 — 다만 **12개를 넘으면 손 좌표가 무너진다.** 아래 "확대" 참조

## 시각 토큰

```
배경      #08080f     노드면    #0c1218
선 유휴   #16323d     선 방문   #22505f
테두리유휴 #1e4453    테두리방문 #2b6a7d
활성 #0ff    성공 #1fd18a    실패 #ff4d7d
```

글로우는 `filter: drop-shadow(0 0 6px <색>)` — 도형에 blur 를 걸면 가장자리가 뭉갠다. **색은 넷뿐**(유휴·활성·성공·실패). 다섯째를 추가하지 말 것 — 한눈에 읽히지 않게 된다.

모든 상태 변화는 `transition: .3s` 가 걸린 CSS 클래스로 간다. 플레이어는 클래스를 붙였다 떼기만 하고 스타일을 직접 애니메이션하지 않는다.

## 경로 타기 — 핵심 트릭

SVG path 위의 위치는 공짜로 얻는다:

```js
function ride(pathId, D, back, err){
  const path = document.getElementById('e_'+pathId), L = path.getTotalLength();
  const c = err ? '#ff4d7d' : '#0ff';
  const dot = document.createElementNS('http://www.w3.org/2000/svg','circle');
  dot.setAttribute('r',4); dot.setAttribute('fill',c);
  dot.setAttribute('filter',`drop-shadow(0 0 6px ${c})`);
  document.getElementById('dots').appendChild(dot);
  const t0 = performance.now();
  (function f(now){
    const k = Math.min((now-t0)/D, 1);
    const {x,y} = path.getPointAtLength(L * (back ? 1-k : k));
    dot.setAttribute('cx',x); dot.setAttribute('cy',y);
    if(k<1) requestAnimationFrame(f); else dot.remove();
  })(t0);
}
```

`ride` 는 **자기 점을 만들고 끝나면 스스로 지운다.** 공유 점 하나로는 fan-out 도, 한 레그가 아직 날아가는 중에 돌아오는 응답도 표현할 수 없다. 가장 자주 틀리는 지점이다.

응답 레그는 **역주행(`back:1`)** 으로 그린다. 같은 선을 거꾸로 타면 되지, 반대 방향 엣지를 하나 더 만들지 않는다.

## 글자 두 줄

다이어그램 아래 정확히 두 줄:

- **상태줄** — 지금 무슨 일이 일어나는지를 **그 시스템의 어휘로**: `GET /orders/8821`, `실측 = "(S4 에서 채움)"`, `HIT`, `SIGNATURE EXPIRED`. `4/11 단계` 같은 건 금지
- **메타줄** — 그 결과: `+38 ms · 누적 96 ms`, `PUSH 차단됨`, `3 / 12 정산`

누적 지연이 시나리오 비교를 가능하게 한다. 정상이 35ms 에 끝나고 캐시 미스가 96ms 에 끝나는 걸 본 사람은 **실제 비용**을 알게 된다 — 정적 다이어그램이 못 전달하는 것.

## 흔적

방문한 노드와 선은 `seen` 클래스를 유지한다 — 활성보다 어둡고 유휴보다 밝게. 트레이스가 끝났을 때 전체 경로가 남아 읽힌다. 반투명 페이드로 구현하지 말 것 — 흐릿함은 역사가 아니라 blur 로 읽힌다.

## 타이밍

한 간격으로 통일하지 말고 단계별 지속시간을 준다. 균일하면 기계적으로 느껴진다:

```
엣지 340ms + 정착 60ms     노드 상태 180ms     시나리오 재시작 2200ms
```

`prefers-reduced-motion` 존중: 점 이동을 건너뛰고 상태만 점프시키되 상태줄은 유지한다.

## 인도 전 체크리스트

- [ ] `NODES` / `EDGES` / `SCENARIOS` 가 플레이어와 분리돼 있다
- [ ] 시나리오 3개 이상, 그중 하나는 중간에 실패한다
- [ ] `ride()` 가 자기 점을 만들고 지운다
- [ ] 응답 레그는 `back:1` — 반대 방향 엣지 복제 아님
- [ ] 선이 노드 박스를 관통하지 않는다
- [ ] 상태줄이 단계 번호가 아니라 도메인 어휘를 쓴다
- [ ] 누적 지연이 보인다
- [ ] 상태 색이 정확히 네 가지
- [ ] 단일 파일, 의존성 0, `file://` 로 열린다
- [ ] `par` 는 실제 동시 구간에만 쓰였다

## 확대

노드 12개를 넘어가면 손 좌표는 유지가 안 된다. **React Flow + dagre/elk** 로 자동 배치를 쓴다 — React Flow 가 엣지 path 문자열을 노출하므로 `ride` 로직은 커스텀 엣지 컴포넌트로 그대로 이식된다. 버전 관리되는 정적 문서가 목적이면 **D2** 나 **Structurizr** 가 맞다(애니메이션을 잃고 diff 가능성을 얻는다).

30노드로 템플릿을 늘리려 하지 말 것. 시스템을 하위 시스템으로 쪼개고 **하위 시스템당 트레이스 하나**를 만든다.
