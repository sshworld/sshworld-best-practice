# orbit — 라우트 흐름 점검

Next.js App Router 라우트를 노드로, `<Link>`/`redirect`/`router.push` 등을 엣지로 삼아
방향 그래프를 만들고 4종 결함을 점검한다.

## 검사 4종

### 1. dangling
엣지 끝에 실존 라우트가 없다. 생성 직후 404 류 — 링크를 추가했지만 대상 페이지 파일이 없는 경우.

### 2. orphan
inbound 엣지 0. 페이지는 완성됐는데 어떤 네비게이션 경로로도 도달할 수 없다.

### 3. sink
outbound 엣지 0. 사용자가 그 화면에서 앱 나머지 부분으로 못 돌아간다 — 갇힌다.

⚠️ 여기서 **프레임워크 렌더 위치를 단정하지 말 것.** 버전·설정에 따라 폴백 동작이 다르고,
단정이 틀리면 틀린 근거로 결함을 보고하게 된다.

대신 **확인 가능한 질문**으로 판단한다:
- `notFound()` 나 에러를 던지는 세그먼트가 있는데, 그 세그먼트(또는 상위)에 수신 파일
  (`not-found.tsx` / `error.tsx`)이 있는가?
- 그 화면에서 앱으로 돌아가는 링크가 있는가?

둘 중 하나라도 아니오면 sink 후보로 보고하되, **근거를 "확인한 것"으로만 적는다**
(예: "어느 파일이 없다", "어느 화면에 링크가 없다"). 프레임워크가 조용히 폴백하므로
**빌드·테스트로는 안 잡힌다** — 이게 이 검사가 필요한 이유다.

### 4. 미폐쇄 흐름
동작에 성공 엣지만 있고 실패 엣지가 없다 / 비로그인·무권한 진입 엣지가 없다 /
비동기 잡의 실패 상태에 복구 경로가 없다.

## 엣지 추출 체크리스트

- 노드: `find src -name "page.tsx"` (src 없으면 `app/` 직하도 확인)
- `<Link href="...">` **및** ``href={`...`}`` 템플릿 리터럴 — 둘 다. 정적 문자열만 grep 하면
  동적 상세 링크를 통째로 놓친다.
- `router.push` / `router.replace`
- `redirect()` — 서버 액션·페이지·middleware 전부
- `middleware.ts` 의 matcher 와 리다이렉트
- **네비게이션 링크 상수 파일을 먼저 찾을 것.** 사이드바·헤더 링크를 컴포넌트가 아니라
  배열/맵 상수로 모아두는 패턴이 흔하다(예: `NAV_LINKS` 같은 역할별 링크 맵, 홈 경로 맵,
  href 생성 함수). `<Link>` 만 grep 하면 이 엣지를 전부 놓쳐 orphan 오탐이 쏟아진다.
  `lib/` `config/` 에서 href 문자열을 담은 배열·Record 를 먼저 훑는다.
- `layout.tsx` 가 공통 Nav/Sidebar 를 렌더하면 그 하위 페이지는 sink 가 아니다.
  레이아웃 경계를 반드시 반영한다.

## 오탐 가드

- 사이드바에 없어도 헤더 로고·홈 리다이렉트로 도달하면 orphan 이 아니다.
  **inbound 는 모든 종류를 합산**한다.
- **진입점은 inbound 0 이어도 orphan 이 아니다** — 루트 `app/page.tsx`, 그리고 외부에서 URL 로 직접 들어오도록 설계된 라우트(인증 콜백, 공유 링크, 결제 리턴 등). 단 "직접 진입 설계"라는 판단의 **근거를 함께 적는다**(어디서 그 URL 이 발급·전달되는가). 근거를 못 대면 면제하지 말고 orphan 후보로 남긴다 — 이 예외는 넓게 쓰면 orphan 검사 자체를 무력화한다.
- 공통 레이아웃 아래 페이지는 자체 링크가 없어도 sink 가 아니다.
- 비동기 처리 흐름은 실패 상태에 복구 경로(재시도·삭제 등)가 있으면 통과.
  중간 상태가 많다는 이유만으로 결함 잡지 말 것.

## 출력 포맷

1. 라우트 그래프 스케치 (묶음별 ASCII)
2. 결함 표: 심각도 / 종류 / 위치(file:line) / 증상 / 한 줄 고침안
3. 통과 항목 표: 무엇을 검사했고 왜 깨끗한지

## 범위

이 스킬의 산출물은 보고서다. 실행 결과로 파일을 고치지 않는다. **수정은 별도 요청**으로 받는다.
Next.js App Router 전용. 다른 프레임워크 대응은 넣지 않는다 (YAGNI).

## 프로젝트에 심을 상시 규칙

스킬은 호출해야 뜨므로 "구현 중 상시" 는 커버하지 못한다. 아래 두 줄을 대상 Next 프로젝트의
`CLAUDE.md` 에 붙여넣어라:

```
- 새 페이지 추가 시 그 페이지로 가는 링크도 함께 추가할 것.
- `notFound()`/에러를 던지는 라우트가 있으면 해당 세그먼트에 `not-found.tsx` / `error.tsx` 가
  있는지 확인할 것 (없으면 사용자가 갇힌다).
```
